维护 Hermes 中文社区（hermes-ai-cn.com）时，一个体会是：中文用户不缺「教程 appetite」，缺的是可复现的端到端路径和与上游对齐的责任边界。翻译 README 只是最低成本动作，社区要长期存活，需要机制设计。

分发：降低「第一次成功」的摩擦

开源 Agent 的流失点常在安装：Python 版本、CUDA、本地模型路径、防火墙。社区应优先提供：

  • 一键脚本或容器镜像（digest 固定）；
  • 「最小可运行」示例仓库，而不是完整巨型 demo；
  • 明确的网络需求（哪些域名必须可达、哪些可离线）。

便携形态（U 盘、离线包）在中文市场仍有真实需求——不是复古，而是环境不可控的现实。

文档：场景先于 API 列表

优秀英文文档习惯 reference-first；中文社区更吃「我先要做出什么」。推荐结构：

  1. 场景卡片（例如：日报汇总、本地文件整理、客服草稿）；
  2. 架构图（数据流、凭据放哪、日志在哪）；
  3. 故障排查（TOP 10 错误信息对照表）；
  4. 最后才是完整 API。

二次开发者的改动，应用「补丁文档」标明与上游差异，避免用户按官方文档操作却失败。

责任边界：社区不是客服外包

常见冲突：用户把上游 bug、本地环境问题、插件作者问题全丢给中文社区志愿者。需要在规范里写清：

  • Issue 模板（环境、版本、复现步骤）；
  • 安全漏洞私下报告渠道；
  • 商业支持 vs 社区互助的界限。

对 OpenClaw / Hermes 这类快速迭代的项目，还要维护版本对照表：哪篇中文文章对应哪个 release，过期文章要顶置警告。

与 AIGC 社区的协同

Agent 与 ComfyUI 用户群重叠，但诉求不同：前者关心「任务完成与权限」，后者关心「画质与节点兼容」。跨社区共享的应是工程实践（缓存、队列、评测），而不是硬揉成一个产品叙事。

中文生态的价值，不在于再造一个封闭平台，而在于让更多从业者能站在上游肩膀上，把最后一公里交付做稳——这也是 369pie 持续写文档、做教学而非仅卖课的原因。
